Core Concepts

1. Experiment, Outcome, Sample Space, Event

Probability starts with four words. An experiment is anything involving chance — tossing a coin, rolling a die, spinning a spinner. One single run of that experiment produces one outcome. Collect every outcome that could possibly happen and you have the sample space. Pick out just the outcomes you care about and you have an event.

Experiment — a situation involving chance.
Outcome — the result of a single performance, or trial, of an experiment.
Sample space — the set of all possible outcomes of an experiment.
Event — a subset of the sample space.
Finite sample space — a sample space that contains a countable number of outcomes.
Infinite sample space — a sample space with outcomes that cannot be counted.
Roll one die:   S = {1, 2, 3, 4, 5, 6}   ← sample space
Event "even number":   S(even) = {2, 4, 6}   ← a subset of S

Notice that the event lives inside the sample space. Every outcome of the event must already be an outcome of the experiment — you never invent new outcomes when you build an event.

2. Finite vs. Infinite Sample Spaces

Sample spaces come in three flavours. Ask yourself two questions: Can I finish listing them? and if not, could I at least line them up in order?

Study Tip — Empty Set: An empty set is a set containing no elements. In probability, if there are no possible outcomes that satisfy an event, then the sample space is described using the empty set ∅. For example, the event "roll a 7 on a standard die" gives S = ∅.

3. Three Ways to Represent a Sample Space

You can represent a sample space by using an organized list, a table, or a tree diagram. All three show the same outcomes — you choose whichever one keeps you from missing any.

Organized list — pair each outcome of stage 1 with every outcome of stage 2 and write them as ordered pairs: S = {(R, R), (R, B), (B, R), (B, B)}. Best for small experiments and when order matters.
Table — stage 1 down the side, stage 2 across the top; each cell is one outcome. Best for exactly two stages (a table has only two directions).
Tree diagram — one level of branching per stage; each complete path from the start to a leaf is one outcome. Best for three or more stages, and the only one of the three that handles a stage whose choices depend on the previous stage.
Study Tip — Tree Diagram Notation: Choose notation for outcomes in your tree diagrams that will eliminate confusion. In the hat example below, R stands for the red hat and B stands for the black hat.
Watch Out — order matters: (R, B) and (B, R) are not the same outcome. The first entry is Saturday's hat and the second is Sunday's hat, so red-then-black is a different outcome from black-then-red. Never merge them into one.

4. The Fundamental Counting Principle

For some large or complicated experiments, listing the entire sample space may not be practical or necessary. To find the number of possible outcomes, you can multiply instead of list.

Key Concept · Fundamental Counting Principle

Words: The number of possible outcomes in a sample space can be found by multiplying the number of possible outcomes from each stage or event.

Symbols: In a k-stage experiment, let
n1 = the number of possible outcomes for the first stage,
n2 = the number of possible outcomes for the second stage after the first stage has occurred, …
nk = the number of possible outcomes for the kth stage after the first k − 1 stages have occurred.

Total possible outcomes = n1 · n2 · n3 · … · nk

Why it works: every one of the n1 first-stage branches splits into n2 second-stage branches, so the tree ends with n1 groups of n2 leaves — that is n1 · n2 leaves. Repeat for each new stage.

Study Tip — Multiplication Rule: The Fundamental Counting Principle is sometimes called the Multiplication Rule for Counting or the Counting Principle.
Watch Out — multiply, don't add: If you choose one item from each category, multiply. You only add when you choose one item from one category or another. Also watch the phrase without replacement: the stage counts then drop by one each time (n, n − 1, n − 2, …).

Common mistakes to avoid:
  • Adding the stages instead of multiplying them (4 + 5 + 2 = 11 instead of 4 · 5 · 2 = 40).
  • Treating (R, B) and (B, R) as the same outcome — position tells you the stage.
  • Counting the number of objects instead of the number of recorded outcomes (12 marbles but only 3 colours).
  • Calling "roll until a 6 appears" continuous. It is endless, but the outcomes can be counted → infinite discrete.
  • Saying two dice have 11 outcomes because the sums run 2 to 12. The sample space has 36 outcomes.
  • Forgetting that "without replacement" shrinks each later stage by one.
  • Listing a leaf of a tree without following the whole path — each outcome is the complete path from Start.
